# CLAUDE.md

Инструмент для оператора «Музыкального лото» (Дмитрий): по брифу собирает игру — 90 песен,
бланки участников (Excel) и презентацию для проектора (PowerPoint), выкладывает на Яндекс Диск.

## Правила для агента

- Отвечай по-русски, простым языком, без терминов: пользователь не разработчик. Перед задачей —
  что делаем и зачем, после — что получилось.
- Перед удалением файлов покажи список и спроси подтверждение.
- Делай одну задачу плана за раз, потом остановись и спроси, идти ли дальше.
- После каждой задачи: допиши в `отчёт.md` (какие файлы создал, переименовал, переместил,
  изменил, удалил; дописывай в конец, целиком не читай), сохрани версию в git и отправь на GitHub.
- После каждой задачи — наглядный результат (для списков и бланков — Excel): ссылка на файл и
  **полный путь от диска** (`C:\Users\User\Documents\Курсы\API\ДВИЖ дз\…`).
- Песни для примеров и игр — вразнобой или под тему, не первые N подряд.

## Где что лежит

- `Панель мероприятий.url` — ярлык на сайт с брифами: https://claude.ai/artifact/QNGUxwrX1AHnyPGuPrzMWN
- `Выгрузка ИИ/` — готовые игры и пакеты игр (папка на мероприятие); в git не хранится.
- `Исходники/` — банки песен и слайдов, шаблоны, архив «Номинация»; в git не хранится.
- `scripts/` — программа, `tests/` — проверки, `artifact/` — панель.
- `Документы/Устройство программы.md` — как устроен код, шаблон и банки: **открывать, когда
  меняешь код**. `Документы/Спецификация.md` — что решено и что сделано.
  `Документы/Архив/` — закрытые планы и спецификации подпроектов: открывать только при нужде.
- `Стоп-лист исполнителей.xlsx` — кого не берём в игры (ведёт оператор; учитывают подбор, сайт и сборка).
- `Идеи.md` — идеи на будущее; `отчёт.md` — история изменений.
- Скиллы `.claude/skills/`: `dezhurstvo` (проверить кнопки на сайте — `/loop 5m /dezhurstvo`),
  `sobrat-igru` (бриф с сайта → готовая игра), `podobrat-pesni`, `nominatsiya`.

## Запреты

- `.env` — ключи (`YANDEX_DISK_TOKEN` и др.), их вписывает оператор. Код берёт через
  `scripts/secret_store.get_secret(name)`. **Никогда не читать `.env` целиком, не выводить
  значения ключей** на экран, в отчёт, коммиты и артефакты; не просить ключи в чат. Проверять
  можно только, заполнено ли значение. В архивы проекта `.env` не включать.
- `Исходники/Номинация.pptx` — **не читать** ни целиком, ни частями; программа только дописывает.
- `Исходники/Старый дизайн/` — только чтение.
- Шаблон `Исходники/Рабочий 2 вар.pptx` не менять; слайды-слоты не заменять целиком.
- PowerPoint закрывать только если `Presentations.Count == 0` (у оператора могут быть открыты файлы).

## Команды

```
python -m pytest -m "not integration" -q   # быстрые проверки
python -m pytest -m integration -q         # с Excel/PowerPoint, ≈6 мин; оператору не копировать
python -m scripts.build_old_bank           # банк старых слайдов (только недостающее)
python -m scripts.common_bank              # общий банк песен
python artifact/build_panel.py             # собрать панель перед публикацией
```

Нужны Windows, Excel и PowerPoint (управляются через COM). `python3` на этой машине —
нерабочая заглушка, использовать `python`.
