# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

# Правила для агента

> Claude читает этот файл в начале каждого нового чата, поэтому правила не нужно повторять в каждом сообщении.

- Отвечай по-русски.
- Перед удалением файлов покажи список и спроси подтверждение.
- После каждой задачи дописывай в файл `отчёт.md`, что ты сделал: какие файлы и папки создал, переименовал, переместил, изменил и удалил.
- Делай одну задачу плана за раз. После неё остановись и спроси, идти ли дальше.
- После каждой задачи сохраняй версию в git и коротко опиши простым языком, что сделано.
- После каждой задачи выдавай наглядный результат: файл (для списков и бланков — Excel) и пиши, где он лежит (ссылкой на файл).
- Пиши простым языком, без терминов: пользователь не разработчик. Перед задачей — что делаем и зачем, после — что получилось.
- Песни для примеров и мероприятий выбирай вразнобой или под названную тему, а не первые N подряд из базы.

## О проекте

Инструмент для оператора мероприятий "Музыкальное лото" (музыкальный
бинго): из брифа (тема/дата/время/место) собираются готовые материалы
для игры — список из 90 песен, бланки участников и презентация для
показа на проекторе.

- **Описание проекта.md** — что делаем и зачем, по RCTC (Роль,
  Контекст, Задача, Ограничения). Короткий вход в проект.
- **Спецификация.md** — согласованная спецификация, собранная из
  разговора с оператором: архитектура, 4 стадии пайплайна, что нужно
  от оператора. Источник истины по архитектурным решениям.
- **План реализации MVP.md** — пошаговый implementation-план (12 задач,
  TDD, с точным кодом) для стадий 1–3 (список песен → бланки →
  презентация). Стадия 4 (визуал: Figma-плагин, Higgsfield) — вне
  текущего плана, отдельная фаза.

## Окружение и реальные входные файлы

Требуется Windows с установленными Microsoft Excel и PowerPoint —
часть скриптов управляет ими напрямую через COM-автоматизацию
(`pywin32`), а не headless-библиотеками, чтобы точно воспроизводить
процесс, которым оператор уже пользуется вручную.

Реальные входные файлы лежат в папке `Исходники/`, но **не коммитятся в git**
(см. `.gitignore` — большие/защищённые авторским правом бинарники).
Пути к ним заданы в одном месте — `scripts/paths.py`, в коде брать их
оттуда:

- `Банк песен.xlsx` — лист `2301`: колонка A = номер, колонка B =
  `"Исполнитель - Название"` (1071 песня).
- `Шаблон бланков.xlsm` — лист `Список` (B2:B91 = 90 песен, E1/E2 =
  кол-во индивидуальных/командных бланков). Содержит VBA-макрос
  `GenerateBlanks.GenerateAllBlanks` — без его запуска бланки не
  формируются, одной записи значений в ячейки недостаточно.
- `Рабочий 3 вар.pptx` — рабочий шаблон презентации, 118 слайдов (все 90
  слотов на макете «Игровой слайд караоке», у каждого кнопка перехода на
  слайд 15 «Таблица»; `Рабочий 2 вар.pptx` — запасной старый вариант); слайды 16–105 — это 90
  слотов-заглушек под бочонки (фигура `"Текст 9"` с текстом-номером).
  Слоты уже содержат рабочую навигацию с вшитыми гиперссылками —
  **заменять слайд целиком нельзя**, только добавлять фигуры поверх
  (см. `scripts/ppt_paste.py` в плане).
- `Банк всех слайдов23.01.2026/` — 1071 файл `.pptx`, имя файла =
  `"Исполнитель - Название.pptx"`, 1:1 соответствует базе песен;
  каждый файл — готовый слайд с видео под конкретную песню.

## Ключи и пароли

Все ключи (например, `YANDEX_DISK_TOKEN` для Яндекс Диска) оператор
вписывает сам в файл `.env` в корне проекта; он в `.gitignore`. Код берёт
их через `scripts/secret_store.get_secret(name)`. **Никогда не читать
`.env` целиком, не выводить значения ключей на экран, в отчёт, в коммиты
и в артефакты; не просить оператора присылать ключи в чат.** Проверять
можно только, заполнено ли значение. При сборке архивов проекта `.env`
не включать.

## Архитектура

`scripts/` — независимые Python-модули, каждый с одной
ответственностью (см. План для точных сигнатур):

- `paths.py` — где лежат исходные файлы оператора
- `song_bank.py` — загрузка и парсинг базы песен
- `validate_selection.py` — проверка утверждённого списка (ровно 90,
  без дублей, все есть в базе)
- `export_selection.py` — экспорт списка с номерами бочонков в JSON
- `generate_blanks.py` — генерация бланков через Excel COM
- `template_slots.py` — поиск слайда-слота по номеру бочонка (чистая
  логика на python-pptx, без COM)
- `ppt_paste.py` — вставка слайда песни из архива поверх слота через
  PowerPoint COM
- `build_presentation.py` — сборка полной презентации мероприятия
- `yandex_disk.py` — загрузка файлов мероприятия на Яндекс Диск и
  публичная ссылка на папку (ключ `YANDEX_DISK_TOKEN` из `.env`)
- `run_pipeline.py` — оркестратор: JSON со списком → готовые бланки и
  презентация одним прогоном

`artifact/index.html` — веб-форма "Панель мероприятий" (Claude
Artifact): приём брифа мероприятия и выдача готовых файлов на
скачивание.
Публикуется не сам `artifact/index.html`, а собранный
`artifact/dist/index.html` со встроенным банком песен (для поиска «песен
по желанию»): `python artifact/build_panel.py`, затем publish файла
`artifact/dist/index.html` с `url`
https://claude.ai/artifact/QNGUxwrX1AHnyPGuPrzMWN. `dist/` в git не
хранится.

Статус: спецификация и план согласованы, выполнение идёт по задачам
плана (см. `отчёт.md` за историей изменений).
