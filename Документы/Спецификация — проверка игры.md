# Спецификация: проверка игры, собранной вручную

Дата: 2026-10-25. Статус: согласовано; работает по скиллу `.claude/skills/proverit-igru/` (первая проверка — «Много рока 2»).

## 1. Зачем

Игры делают два человека: оператор — через Claude (автоматически) и второй человек — вручную,
из того же шаблона «Рабочий 2 вар». У второго человека бывают ошибки: анимация в неправильном
порядке, номинации не выбраны (в презентации лежат все варианты), гиперссылки не сделаны.
Claude проверяет его игру, **сам исправляет то, что можно**, и сообщает, что поменял, чтобы
ошибка не дошла до мероприятия.

## 2. Как это происходит

1. Оператор кладёт комплект второго человека — презентацию, список песен, бланки — в папку
   `Проверка/<папка игры>/` и пишет в чат, например: «проверь игру, тема такая-то, дата такая-то».
2. **Бриф.** Перед проверкой Claude заводит мероприятие в «Панели мероприятий» (как для своих
   игр, с пометкой «проверка игры второго человека»): тема, дата, время, место, тематическая ли
   номинация. Чего нет в сообщении — спрашивает одним сообщением.
3. **Проверка и исправления** (раздел 3) — на копии: оригинал второго человека не меняется.
4. Исправленная копия сохраняется рядом: **«<название оригинала> - проверено.pptx»**.
5. **Отчёт сообщением в чат** простыми словами. **Первым пунктом — «нужно решить вам»**
   (выбор варианта тематического слайда, то, что без человека не исправить); дальше — что было
   не так и что поменял, по бочонкам и слайдам. Если решение оператора нужно посреди работы
   (например, выбрать вариант тематического слайда) — спросить сразу, не дожидаясь отчёта.
   Коротко — то же в заметке мероприятия на сайте; стадии на сайте — «на утверждении».

## 3. Что проверяется и что исправляется

| Что | Исправляет Claude | Только в отчёт |
|---|---|---|
| Порядок анимации **на всех 90 слайдах** (и видео, и старые): первой — песня (видео/звук), запускается сама («вместе с предыдущим» или «после предыдущего», не «по щелчку»), потом текст | ✓ — песня ставится первой, «вместе с предыдущим» | |
| Номинации: ровно одна на раунд | ✓ — лишние варианты удаляются, выбор по очереди «Авто»; игра **записывается в общую историю номинаций** | |
| Тематическая игра: на слайде 10 — тематический слайд | ✓ — если нет или не заполнен: Claude рисует два варианта (как в своих играх), оператор выбирает, выбранный вставляется и дописывается в архив «Номинация» | |
| Кнопки 1–3 «Таблицы» ведут на номинации своего раунда; угловые кнопки ведут на «Таблицу» | ✓ | |
| Тёмный круг под номером на бочонках 3, 6 … 90 | ✓ — добавляется, если нет | |
| На каждом слоте 1–90 стоит песня, номер бочонка верный | | ✓ |
| Песня на слайде совпадает со списком и бланками | | ✓ |
| Старые слайды: настоящие название и исполнитель вместо заготовок, есть звук | | ✓ |
| Видео-слайды: есть видео | | ✓ |
| Исполнители из стоп-листа | | ✓ |
| Размер файла не больше 995 МБ | | ✓ |

## 4. Решения оператора

- Комплект — презентация, список песен, бланки; папка — `Проверка/` (по папке на игру).
- **Список песен и бланки не меняются никогда** — только сверяются с презентацией; исправляется
  только копия презентации. Расхождение — в отчёт «нужно решить вам».
- Второй человек собирает из того же шаблона, что и программа.
- Ошибки исправлять, а не только сообщать; сохранять как «<название> - проверено».
- Номинации, если не выбраны, — по очереди «Авто», игру записывать в историю.
- Бриф перед проверкой: Claude заводит мероприятие на сайте; оператор чаще пишет данные в чат.
- Тематический слайд, если не заполнен, Claude заполняет (два варианта на выбор).
- Когда нужно решение оператора — писать об этом в первую очередь.

## 5. Выбор Claude (оператор может поправить)

- То, что без человека не исправить (песня не совпадает со списком, песня из стоп-листа, нет
  видео, файл больше 995 МБ), — только в отчёт, презентация в этом месте не меняется.
- Папка `Проверка/` — в корне проекта, в git не хранится.
- На Яндекс Диск проверенная игра не загружается (оператор не просил).
- Запуск — из чата (скилл «проверить игру»); кнопки на сайте для проверки нет.

## 6. Что считается провалом

- Оригинал второго человека изменён.
- Исправленная копия «сломала» то, что было правильным (например, перепривязала верную кнопку
  не туда).
- Ошибка из таблицы раздела 3 не найдена или не попала в отчёт.
- Отчёт написан непонятно для оператора.

## 7. Как проверить

Пробная проверка: копия одной нашей игры с намеренно внесёнными ошибками (неверный порядок
анимации на двух старых слайдах, все варианты номинаций, кнопка 2 ведёт не туда, нет круга на
одном слайде, одна песня не совпадает со списком). Ожидается: первые четыре исправлены, пятая
— в отчёте «нужно решить вам»; оригинал не изменён.

## 8. Уроки первой проверки («Много рока 2», 25.10.2026)

- Номер бочонка на слайде искать по тексту-числу в верхней части слайда, а не по имени фигуры: PowerPoint
  и python-pptx называют фигуры по-разному («Текст 9» / «Text 9»), проверка по имени молча пропускала все слайды.
- Ошибка порядка анимации бывает и на видео-слайдах (бочонки 38, 43, 62: текст раньше видео; на 38 видео ждало щелчка).
