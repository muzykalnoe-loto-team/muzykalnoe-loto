## 1. Контекст: что такое музыкальное лото

Развлекательное мероприятие. Участники получают бланки с песнями (сетка,
часть клеток занята названиями песен). Ведущий тянет бочонки (всего 90 шт),
каждому номеру бочонка соответствует слайд презентации, на котором
включается конкретная песня. Участники поют и зачёркивают эту песню в
бланке, если она у них есть.

## 2. Цель проекта

Дать оператору (владельцу) инструмент, в который вводятся дата, тема, время
и место мероприятия, и на выходе получаются все материалы для его
проведения: список песен, бланки участников, презентация для показа и
визуал для соцсетей.

## 3. Архитектура

Единая точка входа — веб-артефакт "Панель мероприятий" (форма ввода брифа).
Форма — это "бриф": она сохраняет данные о мероприятии в общую базу
артефакта со статусами по стадиям. Фактическую генерацию (подбор песен,
сборку бланков, сборку презентации, генерацию визуала) выполняет ассистент
(Claude) в рабочей сессии — не мгновенно, а по мере обработки брифа.
Готовые файлы заливаются обратно в артефакт, где их можно скачать.
Переход к следующей стадии — только после явного утверждения оператором
в UI.

Почему не полностью автоматический веб-сервис "по кнопке за секунды":
потребовал бы отдельного хостинга и бэкенда для генерации PPTX/PDF/картинок
— это отдельная разработка, избыточная на старте.

## 4. Модель события (что хранится в базе артефакта)

- тема, дата, время, место, количество участников (N)
- статус по каждой из 4 стадий: `черновик → на утверждении → утверждено`
- список 90 песен с привязкой к номеру бочонка (1–90)
- ссылки/файлы: бланки, презентация, афиши, сторис

## 5. Пайплайн: 4 стадии

### Стадия 1 — Список песен ✅ сделано
- **Вход:** тема, база песен оператора (Excel, ~1600 песен + исполнители)
- **Процесс:** ассистент подбирает ~90 песен под тему, расставляет по
  номерам бочонков 1–90. Обязательно входят песни по желанию из брифа и
  не меньше 5 суперхитов — песен, которые знают и поют все, даже гости
  без подготовки (эталон — «Жуки - Батарейка»)
- **Выход:** список на утверждение
- **Согласование:** оператор утверждает или отправляет на правки

### Стадия 2 — Бланки ✅ сделано
- **Вход:** утверждённый список 90 песен, Excel-шаблон бланков оператора
  (уже существует, сам генерирует бланки по вставленному списку)
- **Процесс:** ассистент вставляет список в указанный столбец шаблона
- **Выход:** готовый файл бланков на N участников, в артефакте на скачивание
- **Примечание:** логика самой генерации бланков уже реализована в Excel
  оператора и в scope проекта не входит — только подготовка списка и его
  вставка

### Стадия 3 — Презентация ✅ сделано
- **Вход:** утверждённый список 90 песен, архив слайдов (1600 файлов,
  один файл/слайд на песню, назван по песне/исполнителю), шаблон
  презентации (будет передан отдельно оператором)
- **Процесс:** ассистент находит нужные 90 слайдов по названию, собирает
  их по порядку номеров бочонков в единый файл на основе шаблона
- **Формат:** "проекторный" — широкоформатный показ на большом экране/
  проекторе (16:9, крупный текст, высокая контрастность)
- **Выход:** один .pptx файл, полностью соответствующий списку и бланкам

### Стадия 4 — Визуал (афиши и сторис) ⬜ не сделано (фаза 2)
- **Вход:** тема, дата, место; Figma-файл оператора (автолейаут,
  компоненты, брендинг); Higgsfield API для генерации изображений
- **Процесс:**
  1. Генерация фоновых изображений под тему через Higgsfield API
     (например, "белая вечеринка" → люди в белом, танцуют)
  2. Чтение палитры/шрифтов/структуры автолейаута из Figma через
     Figma REST API
  3. Формирование рендер-заданий (фон + тексты: дата/тема/место) —
     3 варианта афиш, 10 вариантов историй
  4. Оператор открывает Figma, запускает Figma-плагин — плагин подтягивает
     рендер-задания и раскладывает их по компонентам автолейаута
- **Выход:** редактируемый .fig-файл с готовыми афишами и сторис
- **Техническое ограничение:** Figma REST API умеет надёжно читать файл
  (цвета, шрифты, автолейаут, экспорт PNG), но не умеет программно
  вписывать контент в существующий фрейм без плагина внутри самой Figma —
  поэтому результат собирается через плагин, а не "по кнопке" в артефакте

## 6а. Подключения к внешним сервисам

### Яндекс Диск ✅ подключён (2026-10-07)

- **Зачем:** готовые файлы мероприятия (список песен, бланки,
  презентация ~1 ГБ) не помещаются в панель мероприятий (лимит ~20 МБ),
  поэтому кладутся на Диск оператора, а в панель — ссылка на папку.
- **Способ подключения — REST API Яндекс Диска** (`cloud-api.yandex.net`),
  напрямую из Python (`scripts/yandex_disk.py`, только стандартная
  библиотека). Не CLI и не MCP: официальных нет, а обёртки не нужны.
- **Доступ (OAuth):** на oauth.yandex.ru заведено приложение
  «Музыкальное лото» с правами «Чтение всего Диска», «Запись в любом
  месте на Диске», «Доступ к информации о Диске». Его ClientID —
  `YANDEX_CLIENT_ID` в `.env` (не секрет); ключ (токен) —
  `YANDEX_DISK_TOKEN` в `.env` (секрет, никому не передавать).
- **Срок ключа:** около года. Обновить: открыть
  `https://oauth.yandex.ru/authorize?response_type=token&client_id=<YANDEX_CLIENT_ID>`
  → «Разрешить» → вставить новый ключ в `.env` после
  `YANDEX_DISK_TOKEN=` → сохранить.
- **Если ключ утёк:** Яндекс ID → «Безопасность» → «Устройства и
  доступы» (id.yandex.ru/security) → отозвать доступ приложения
  «Музыкальное лото», затем получить новый ключ.
- **Раскладка на Диске:** `Музыкальное лото/<дд-мм-гггг> <тема>/` →
  «Список песен.xlsx», «Бланки.xlsm», «Презентация.pptx». К папке
  открывается доступ по ссылке (скачать может любой, у кого есть ссылка);
  ссылка пишется в панель (кнопка «Скачать файлы») и в ярлык
  «Файлы на Яндекс Диске.url» в папке мероприятия.
- **Ограничения бесплатного Диска:** 10 ГБ всего (на 2026-10-07 свободно
  5,9 ГБ), один файл — до 1 ГБ. Мероприятие ≈ 1 ГБ, поэтому папки
  прошедших игр удаляются с Диска — только с подтверждения оператора
  (на компьютере они остаются в `events/`). Программа заранее проверяет
  место и размер файлов и не начинает загрузку, если не поместится.
